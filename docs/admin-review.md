서버는 단일 관리자 역할만 지원한다. 아이디/비밀번호는 환경변수의 아이디 및 scrypt 해시로 검증한다. 임의의 클라이언트 역할/로컬 키는 신뢰하지 않는다. 세션 원문은 HttpOnly/Secure/SameSite=Strict 쿠키에만 보관하고 DB에는 해시만 기록한다. 1시간 절대 만료, 비밀번호 또는 아이디 변경 시 기존 세션 무효화. 읽기 API에도 세션 필수, 변경 API에는 Origin과 CSRF 토큰 모두 필수. 전역 5분/실패 10회 제한은 보수적인 기본값이며 운영에서는 IP별 프록시 제한도 추가한다. 전역 제한은 공격자가 관리자 로그인을 잠시 막을 수 있으므로 모니터링한다.

## 운영에서 먼저 확인할 사항

1. www.dynov.kr을 배포하는 실제 저장소, 브랜치, 커밋, 도메인 연결 및 관리자 경로를 호스팅 대시보드에서 확인한다. 이 오래된 저장소로 운영 홈페이지를 덮어쓰지 않는다.
2. 현재 문의 저장소의 소유 계정, 스프레드시트/테이블, 필드 이름, 타임스탬프 형식, 건수 및 중복을 확인한다. 저장소 inquiry.js에는 공개 제출용 Google Apps Script URL이 있지만 GAS 소스/배포 권한은 포함되지 않았다. **개인정보 조회를 위해 그 URL을 임의 호출하지 않았다.** GAS doGet 목록 공개 여부를 소유자 설정에서 확인하고, 공개 조회가 있다면 먼저 차단한다. 새 관리자 API만 보호해도 옛 공개 API까지 보호되지는 않는다.
3. 원본 문의와 각 사용 브라우저의 로컬 상태를 각각 백업한다. 브라우저별 메모는 서버에 존재하지 않으므로 자동 복구할 수 없다.
4. 아래의 명시적 이전을 수행하고 건수·필드·상태·메모를 대조한다. 기존 제출 폼은 그대로 유지했다. **새 문의를 이 SQLite DB에 연속 반영하는 연결은 아직 구현하지 않았다.** 실제 수집 환경 확인 후 서버 전용 동기화 작업 또는 기존 DB 어댑터를 추가해야 하며, 이 조건 전에는 실사용 전환하지 않는다. 공개 폼에서 관리자 API를 호출하거나 브라우저에 서비스 계정 키를 넣지 않는다.
5. HTTPS 동일 출처로 관리자 정적 파일과 /api/admin/* 프록시를 제공한다. GitHub Pages만으로는 Python API를 실행할 수 없다. 실제 운영이 다른 프레임워크라면 API 계약을 해당 서버에 이식하거나 별도 서버를 프록시한다.
6. 운영에서 로그인/오류/로그아웃/만료/다른 브라우저의 미인증 접근/검색/한글 CSV/메모 동시 수정/새 문의 도착을 검증한 후 전환한다. 별도 스테이징 브라우저 E2E 및 실제 GAS 연동은 아직 검증하지 않았다.

## 서버 실행 예시 (호스팅 운영자가 설정)

Python 3.12 이상. 표준 라이브러리만 사용하는 WSGI 앱이다. 개발용 http.server로 인터넷에 공개하지 않는다. 운영 WSGI 서버(예: gunicorn)는 호스팅 환경에서 설치·버전 고정한다.

```bash
python server/app.py hash-password
# 출력된 해시를 호스팅의 secret 설정에 등록. 실제 값은 git에 넣지 않는다.
# ADMIN_USERNAME: 관리자 아이디
# ADMIN_PASSWORD_HASH: 위 scrypt 해시 (salt:hex)
# ADMIN_ORIGIN: https://www.dynov.kr (실제 관리자 출처, 끝 / 없음)
# ADMIN_DB_PATH: /var/lib/dynov/admin.sqlite (웹 루트 밖, 영구 볼륨)
gunicorn --bind 127.0.0.1:8001 --workers 2 server.wsgi:application
```

프록시에서는 /api/admin/*만 WSGI에 전달하고 다른 공개 사이트 경로는 기존 배포를 유지한다. API 응답은 캐시하지 않는다. TLS 종료, 프록시 타임아웃/본문 제한/IP별 로그인 제한을 설정한다. DB 디렉터리 0700, DB 0600, 암호화된 백업 및 복원 검증, 개인정보 보존 기간을 설정한다. 다중 인스턴스에 로컬 SQLite를 각자 두지 않는다(단일 영구 DB 볼륨 또는 별도 공용 DB 필요). 세션 및 요청 본문을 접근 로그에 기록하지 않는다. 서버 환경변수를 바꾸는 것 외에 코드 내 인증값은 없다.

## 기존 데이터 보존·이전

원본 문의 JSON 배열에는 안정적인 id가 권장된다. 없으면 **기존 문자열 그대로의 timestamp**를 식별자로 사용한다. 임의의 날짜 정규화를 하면 로컬 상태 키와 연결되지 않을 수 있다. 중복 timestamp는 이전 전 해소한다. 가져오기는 기존 동일 ID의 레코드를 덮어쓰지 않으므로, 중복 ID가 있는 원본은 먼저 대조해야 한다.

```bash
python server/app.py import /secure-backup/inquiries.json
python server/app.py import-state /secure-backup/legacy-state.json
```

원래 사용하던 브라우저·동일 출처에서 개발자 도구로 다음 **읽기만 하는 코드**를 실행해 출력 JSON을 개인 백업 파일에 저장한다. 채팅이나 공개 저장소에 올리지 않는다.

```javascript
JSON.stringify(JSON.parse(localStorage.getItem('dynov_admin_state_v1') || '{}'), null, 2)
```

import-state는 {"기존 id 또는 timestamp":{"status":"review","note":"메모"}} 형식을 받는다. 기존 서버 편집이 있거나 ID가 없으면 전체 트랜잭션을 취소한다. 브라우저 여러 개의 파일은 사람이 충돌을 대조한 뒤 통합한다. 인증용 옛 로컬 키만 새 페이지에서 삭제하며, 상태 키는 삭제하지 않는다. 이전 확인 전 원본 시트/로컬 상태/백업을 삭제하지 않는다. 롤백할 때 서버 DB 백업도 보존하고, 노출된 예전 패스코드 방식으로 되돌리지 않는다.

## 검증 명령

```bash
python -m unittest discover -s tests -v
node tests/admin-client.test.cjs
node --check js/admin.js
```

API 접근 차단, Origin/CSRF, 로그아웃, 서버 저장/버전 충돌, 재가져오기 보존, 비밀번호 변경 후 세션 무효화, 이전 트랜잭션 취소, 로그인 제한을 검증한다. JS 검사는 DOM 스텁 기반이며 HTML/URL 인코딩, 검색/필터, CSV 수식 차단을 확인한다. 실제 브라우저 레이아웃·다운로드 E2E는 별도 필요하다.
